# つま先支持と開口部30mm帯の指接触

`config/pose_patterns.yaml` の既定値を、つま先付近だけを支持するモデルへ変更した。
開口部はObiの有限質量の布として動き、右グリッパーの実形状と接触する。
保存済みheld-A形状、足の寸法、靴下の自然長は変更していない。
従来の75mm固定モードと保存済み画像はそのまま残している。

## 領域と解き方

| 領域 | 処理 |
| --- | --- |
| 開口部から材料長30mm以内 | 96粒子をObiの動的な布として解く。右指との接触を許可 |
| 足のつま先付近 | 隣接する2断面・64粒子のみ位置を支持 |
| 下垂部 | 断面ごとの質量・重力・長さ・曲率・離れた断面間の接近を解き、表面が追従 |
| 足と布 | 現在の姿勢の皮膚を囲む既存の凸包とCoulomb摩擦による接触補正を維持 |

支持の種となるパッチは、つま先ボーンではなく、現在の足の皮膚の最遠端から選ぶ。
ボーン位置は実際の指先より手前にあるためである。
検証した姿勢では支持は材料座標37.5–50mmまたは50–62.5mmの2断面となった。
30mm帯に固定粒子はない。開口から支持点までを一括固定する処理は行わない。

右指のObiColliderに専用カテゴリーを割り当て、布の接触マスクで帯外を除外する。
境界をまたぐ三角形を通じた接触漏れを避けるため、面の全頂点が帯内であることを要求する。
現在の長手メッシュ間隔は12.5mmなので、30mm指定には材料座標0・12.5・25mmの断面が含まれる。
厳密に30mmまでの面を必要とする場合は、30mm位置でのメッシュ分割が必要である。

自己接触用のサンプリング半径7mmと、外部物体との接触厚みは分けている。
指の接触は粒子半径とコライダーのcontact offsetの和を2.5mmとする。
指や足のメッシュを拡大・縮小して隙間を作る処理は行わない。

## 下垂部の接続

従来の断面の探索・補間をそのまま使うと、つま先直後の異なる断面に頂点が結び付いて
折れや自己交差が生じた。新モードでは各頂点を自身の材料断面へ対応させ、
断面の向きを4区間で連続的に接続する。中心線の曲がり過ぎも抑える。
交差が残る場合は接続範囲2・3・6・8区間を順に試し、交差検査を通らなければ拒否する。

足首の角度を変えるたびに新しいPlayerで準備する。
同じネイティブ衝突ワールドへ足のメッシュを繰り返し追加する方式では、
コライダーハンドルの再利用時にPlayerが終了するケースが確認されたためである。
通常のプレビューは複数番号の指定時に自動的にPlayerを分ける。
`--reuse-player` は切り分け用で、検証済みの再生成手順には含めない。

## 検証結果

`artifacts/toe-contact-final/summary.json` に結果と入力レポートへのパスを保存した。

- Excel 50行に含まれる32種類の足首角度を物理試行し、50行すべてへの対応を記録した。
- 64支持粒子の位置誤差は0m。30mm帯の96粒子はすべて有限質量で、固定粒子は0。
- 各試行の最終状態と追加保持後で、足の皮膚との交差・布の自己交差検査を通過した。
- 下垂部の断面中心線の最大折れ角は、以前の約37–42度から約19–24.5度へ低減した。
  表面のしわ角度とは別の幾何学的な指標である。
- 姿勢13では速度値に小さな振動が残る。全頂点を追加計測し、1秒間の最大変動は約1.37mmだった。
  速度0.1m/s未満かつ1秒間の全頂点変動2mm未満という静止基準で受け入れた。
  その他の姿勢は自由部分の最大速度0.05m/s未満の基準を満たした。
- 代表姿勢1では、Dry-AIRECの指の衝突メッシュを複製した検査治具で、
  帯内の接触インパルスと約29mmの布変位を確認した。帯外の治具試験の接触は0。
  帯外粒子が指と接触した記録も0だった。

接触治具は右腕を動かすものではない。腕の到達性、足と指の衝突回避、
二指での把持成立・滑り・保持成功は今後の検証対象である。
表面交差検査も、あらゆる共面接触・体積包含を保証するものではない。

## 実行

```bash
SOCK_BUILD_LOG_DIR=/tmp/sock-toe-contact-build \
  ./scripts/build_custom_player.sh development Build/SockDressingPlayer/ToeContactV6
python3 scripts/preview_pose_patterns.py --numbers 1 14 39
# 画像なしで全50行を再生成
python3 scripts/preview_pose_patterns.py --headless
# 実指メッシュの帯内外接触を検査し、Unity画像も保存
python3 scripts/validate_toe_contact.py --settle-steps 150 --graphics
```

通常プレビューの出力先は `artifacts/sock-pose-pattern/toe-contact/`。
物理試行は150ステップ（3秒）の準備と5ステップの追加保持を使う。
保存済みの検証結果は `artifacts/toe-contact-final/`、Unity画像は
`artifacts/toe-contact-final/contact-response/side.png` と `dorsal.png` にある。

`SockDressingEnv.begin_cloth_contact_rollout()` は、検査済みのこのモードでは
支持・接触マスクを保って接触ロールアウトを開始する。全固定の視覚モードは引き続き拒否する。
既存の `grasp()` APIは布粒子の拘束を作るAPIであり、物理的な指の閉鎖による把持判定とは異なる。

## 適用範囲

このモデルは、リーチングと開口部の局所接触を試すためのもの。
下垂部は縮約モデルであり、布全体をObiだけで解いているわけではない。
つま先支持は維持されるため、靴下全体を引き上げる段階では支持解除と双方向の力の結合が必要となる。

Excelのpitch・rollだけを適用し、開口位置は保存済みAのままである。
S01–S05の素材差、B–Eの挿入段階、しわ・ねじれ・折り返しの追加生成は適用していない。
同角度の行は同じ物理試行に対応する。

以前のモードは `config/pose_patterns_legacy_drape.yaml` と
[旧モデルの記録](pose_patterns_legacy_drape.md) で再現できる。
