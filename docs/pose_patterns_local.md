# 休止中の局所変形モード

現在の既定設定は[held形状から足首姿勢だけを変えるモード](pose_patterns.md)です。
以下の局所変形を再開する場合は、設定を別ファイルに複製し、`pose_pattern.held_reference`を削除して、
`--config`と`--output`を明示してください。

# Excelの50パターンを静止形状として再現する

`config/pose_patterns.yaml`は、視覚からの把持位置探索に先立って靴下の見た目を確認する設定です。
Excelの統合パターン表50行を読み込み、足首姿勢と靴下形状を生成します。
S01〜S05は識別ラベルとして保持し、寸法・素材特性には差を付けません。

## 基準と単位

- pitch 0°：足先軸が水平、足の甲側が鉛直上向き。
- pitch正：足首位置を保ってつま先を持ち上げる向き。Excelの30〜50°をそのまま適用。
- roll正：pitch適用後の、足首からつま先へ向かう軸まわりの右手方向。
- 前後ずらし正：開口をつま先側から踵・下腿側へ進める向き。表のcmをmに変換。
- 斜め回転正：開口付近の足の甲方向を軸とする右手方向。足首のrollとは別に布の開口面を傾ける。
- 回転順序：足首はpitch、次にroll。靴下の斜め回転はその姿勢に追従した座標系で適用。
- Eの高さ：従来と同じくDから下腿軸方向に5 cm。前後ずらしはこの位置に別途加算。

roll・斜め回転・前後ずらしの符号は、ユーザーから個別の指定がなかったための実装上の規約です。
設定の`pose_pattern.signs`の`roll`・`diagonal`・`shift`をそれぞれ`-1`にすれば反転できます。
世界の上方向はUnityのY軸です。骨の内部Euler角をそのままpitchとして扱うことはせず、
足先のワールド方向を検査して指定したpitchと一致することを確認します。

A〜Dの位置は[既存の経路定義](preinsert_normal.md)に従います。
Excelの表は変更しません。計算済みのK列・M列から最終版のpitch・rollを読み取り、
実測角度の記入欄や「入れ替え前後比較」シートの古い角度は使用しません。
数式のキャッシュ値が欠ける場合は停止します。

## 大きさと局所変形

靴下の基準形状は、足・下腿スキンの断面の輪郭に沿う多角形から作ります。
以前の大きな楕円断面や、断面の最大径を靴下全体へ広げる処理は使いません。
斜め回転も、傾けた断面に対して足を囲う形を計算します。
接触余裕の設定は2.5・3.5・5・6 mmの範囲で検査し、最小の通過値を採用します。
自由部分の基準半径は18 mmです。

しわ・つぶれ・ねじれ・折り返しは、**条件ごとに合計1〜3箇所の局所変形**として作ります。
指定された種類をそれぞれ少なくとも1箇所に含めます。変形のない条件は0箇所です。
周期的な波は使わず、一つの変形が一つの有限範囲で終わり、その外では元の形状を保ちます。
折り返しも開口の選ばれた部分だけで、全周には作りません。

標準の変形尺度は`amplitude_m: 0.015`（1.5 cm）で、1〜2 cmの範囲で変更できます。
箇所ごとに大きさ・幅・位置を少し変え、規則的な並びを避けます。
`seed: 1729`とExcelの通し番号から乱数を作るため、同じ設定では同じ形状になります。
`seed`を変えると配置が変わります。S01〜S05のラベル自体は寸法・配置に影響しません。

|Excelの条件|実装|
|---|---|
|通常|足の断面に沿った基本形状|
|つぶれている|局所的に余った布の中に谷を作り、足の表面より内側へは潰さない|
|折れ・よれ|一つの局所的な盛り上がりと軸方向のずれ|
|軽いしわ|選んだ箇所だけに単独の盛り上がり|
|かかとねじれ|踵に近い部分で布を輪郭に沿ってずらし、局所的にねじる|
|全体ずれ|Excelの前後ずらしに加えて、靴下側の位置ずれを適用|
|内巻き／外巻き|選んだ開口の一部分だけを内側／外側へ折り返す|

足の下に入る凹みは皮膚を貫通するため、足の輪郭を保護します。
内巻きの二層を離すために必要な余裕も、その箇所だけに加えます。
安全検査に失敗した場合は局所変形の配置を変えて再試行し、
靴下全体を数cm膨らませて通過させることはありません。
各部の変位は足の輪郭や折り返しの構造によるため、厳密な±1.5 cmではありません。
足表面は現在のスキンメッシュから作った足・下腿の凸包で近似します。

各`report.json`には以下を記録します。

- `baseline_cuff_perimeter_m`・`cuff_perimeter_m`：局所変形前後の開口外周。
- `local_feature_count`・`local_features`：箇所数、種類、位置、幅、大きさ。
- `changed_particle_fraction`：基準形状から位置が変わった粒子の割合。
- `random_seed`・`feature_variant`：再現に使う乱数設定と安全検査の再配置番号。
- `clearance_m`：断面生成に使用した接触余裕。

各形状に対し、以下の独立した幾何学検査を行い、失敗した形状は採用しません。

- 布の頂点が足・下腿の内部に入っていない。
- 布の辺が足・下腿を横切っていない。
- 足・下腿の辺が布の面を横切っていない。
- 布の辺が、頂点を共有しない別の布の面を横切っていない。

この検査は辺と面の貫通を調べるもので、任意の共面接触や最小の層間距離を数学的に保証するものではありません。

## 実行

```bash
python3 -m pip install -e '.[fit,test]'
SOCK_BUILD_LOG_DIR=/tmp/sock-pattern-build \
  ./scripts/build_custom_player.sh development Build/SockDressingPlayer/PosePatterns
python3 scripts/preview_pose_patterns.py
```

既定で50パターンを生成します。番号はExcelの通し番号です。

```bash
# 一部の条件を確認
python3 scripts/preview_pose_patterns.py --numbers 3 6 10
# ランダム配置を変える
python3 scripts/preview_pose_patterns.py --numbers 3 --seed 200
# 変形量を2 cmにする
python3 scripts/preview_pose_patterns.py --numbers 3 --amplitude-m 0.02
# 画像を作らず角度・形状・保持を検査
python3 scripts/preview_pose_patterns.py --headless
# Unityを起動せず、表の読み取り結果と座標規約だけを出力
python3 scripts/preview_pose_patterns.py --manifest-only
```

描画には利用可能な`DISPLAY`が必要です。画像はUnityの実際のメッシュを描画したものです。
確認時にはロボットの表示だけを一時的に隠し、布には形状由来の陰影を付けます。
材質・カメラ切り替え後に描画を一度完了させてから画像を取得し、切り替え前のフレームの混入を防ぎます。
側面画像のカメラ方向は水平基準を保ち、pitchの差を見比べられるようにしています。

## 保存した検証結果

`artifacts/sock-pose-pattern/workbook-visual-local/`に、標準1.5 cm・seed 1729の全50パターンを保存しました。
全条件で指定pitchの読み戻し、交差検査、5物理ステップの静止保持を確認しました。
旧版との開口外周の比較は`size-comparison.json`、代表例の比較画像は`size-comparison.jpg`です。
50条件の平均外周は45.9 cmから34.3 cmへ縮小しました。
1番は51.0→30.3 cm、6番は44.7→29.7 cm、変形のない13番は35.2→27.7 cmです。
以前の物理held状態はA約26.5 cm・D約31.3 cmですが、足首姿勢や前後ずらしが異なるため同一寸法には固定しません。

- `overview-1.jpg`〜`overview-5.jpg`：各10パターン、側面と足の甲側からの比較一覧。
- `manifest.json`：Excelから読んだ全条件、単位・符号の規約、入力ファイルのハッシュ。
- `report.json`：条件ごとの検査結果と失敗一覧。
- `01-S01/`など：`side.png`・`dorsal.png`・`views.jpg`・検査結果・形状データ。
- 各`visual-state.json`：姿勢条件、粒子位置、辺・面、現在の足・下腿形状。
- 各`runtime-config.yaml`：同じパターンを再生成するための設定。

通常の`SockDressingEnv`も`config/pose_patterns.yaml`を読み込むと、`apply_scenario()`の末尾で
`pose_pattern.number`のパターンを初期化します。50条件を切り替えるプレビューコマンドでは、
共通シーンの上で`initialize_pattern()`を繰り返し呼びます。

## 動作の範囲

今回のモードは、生成した全粒子の位置を明示的に保持します。物理ステップを進めても
自由な垂れ下がりや落下が起きないため、以前の自由部分の運動による自己交差を抑えられます。
これは張力・摩擦による保持の検証ではなく、[外周フィットの物理モード](circumference_fit.md)と分けています。
両モードを同時には使用できません。

リーチングや把持周辺だけの変形は今回の範囲には含みません。
この固定状態をそのまま把持成功と判定しないよう、`begin_cloth_contact_rollout()`は開始を拒否します。
次の段階で、把持付近の拘束だけを弱める処理と実際の接触・把持判定を接続します。
