# 右グリッパーの把持中心と32姿勢の幾何探索

## 実皮膚コライダーへの変更

現在の既定Playerは剛体接触用の足形状をBake済み実皮膚へ変更している。
実装と検証方法は [rigid_skin_contact.md](rigid_skin_contact.md) を参照。
以下は変更前のPlayerに対する探索記録で、「現在の足凸包」はその時点の旧剛体形状を指す。
布の安定化に使う内部凸包は現在も維持するが、右手との剛体衝突には使わない。

## 布を挟む配置の追加確認

[候補配置のUnity画像と布との交差検査](../artifacts/grasp-candidate-photos/README.md) を追加した。
足に対する非干渉は、指と布の交差がないことや把持成立を保証しない。
No.1で撮影した4配置のうち、5〜10mm開きの3例は布と交差し、50mm開きの1例は
布との交差がなく、局所的に内外の把持面の間に布があることを確認した。
布との交差除外と、有限の把持面に布が収まる条件を後段の候補選別に追加した。
[再選別の仕様と結果](grasp_cloth_screen.md)を参照。閉鎖・保持の成立は引き続き未検証。

## 変更前の探索結果

32種類の足首角度に対して、合計860,160姿勢を検査した。
**実際の皮膚形状では全32姿勢に無干渉候補があるが、現在の足の凸包接触形状では、今回の条件を満たす候補は0だった。**
足の表示形状と接触形状の差を解消する前に、これらをシミュレータで実行可能な把持候補として採用しない。
足・靴下の形状や既存シミュレータの接触設定は、この探索では変更していない。

| 判定対象 | 結果 |
| --- | --- |
| 実際の皮膚三角形、余裕1mm | 32/32姿勢で候補あり |
| 指の接触が有効な布面上の皮膚無干渉候補 | 合計10,790姿勢、各足首角度で220–456姿勢 |
| 候補のある布上のサンプル点 | 各足首角度で31–44点 |
| 現在の足凸包も含めた無干渉候補 | 0/32姿勢。余裕を要求する以前に、足凸包と交差 |

足凸包だけでも全候補と交差しており、下腿凸包だけが原因という結果ではない。
追加で、皮膚の1mm余裕条件を通らなかった姿勢も含む元の860,160姿勢を足凸包だけで検査し、
指接触有効面上の終端5mm姿勢には、余裕ゼロでも非交差候補がないことを確認した。
有限の位置・方向グリッドと指定の閉鎖姿勢による結果であり、連続空間全体の不可能性を証明するものではない。

## 把持中心の定義

「衝突メッシュの実先端から手のひら側10mm、左右の指の間・幅方向の機械的中心軸上」とした。

- URDFの `right_gripper/gripper_base` 基準：**(264.682423, 0, −40) mm**。
- 同じリンクのUnity局所座標：**(0, −40, 264.682423) mm**。
- 衝突メッシュ実先端はURDF基準X=274.682423mm。
- 既存 `grasping_frame` はX=255mmなので、指定中心はそこから指先方向へ9.682423mm進んだ位置になる。
  既存URDFのフレーム自体は書き換えず、探索用TCPと、対応するベースの位置・姿勢を出力した。
- 把持中心断面・幅中央の凸包内側面間を50mmとするURDF関節値は、finger=0.058654642m、mimic=0.029327321m。
  50mmをそのままfinger関節へ与える定義ではない。値はURDF単位で、Unity制御APIの単位変換は別途必要。

手のひら、左右の指の付け根、左右の指の計5メッシュを使用した。
実行時のURDF importerが `MeshCollider.convex=true` を設定し、Obiも凸な衝突形状へ変換するため、
各部品の衝突STLの凸包で判定した。手全体を一つの凸包へまとめてはいない。
ROS→Unityの反転も含めて変換し、回転・移動した実皮膚と同じ座標で比較している。

## 探索条件

設定は `config/right_grasp_geometry.yaml` に保存した。

| 項目 | 条件 |
| --- | --- |
| 対象状態 | `artifacts/toe-contact-final/summary.json` の検査済み32種類 |
| 帯領域 | 開口からつま先方向の材料長0–30mm |
| 位置 | 周方向32点 × 深さ0・5・10・15・20・25・30mm＝224点 |
| 方向 | 布面内yawを30度刻みで12方向、傾き−60・−30・0・30・60度、指の割り当て2方向 |
| 姿勢数 | 各点120方向、各足首角度26,880姿勢 |
| 最大内側開き幅 | 50mm。5・10・20・30・40・50mmを検査 |
| 終端の仮定 | 内側開き幅5mm。現在の外部接触半径2.5mm/指に対応する幾何検査用の値 |
| 足との余裕 | 1mm |
| 接近 | 最後の50mmを手先の進行軸に沿って直進、姿勢一定 |
| 閉鎖 | 選択した開口幅から5mmまで、手の位置・姿勢一定 |

5mmはユーザーが決めた実布厚みや最終把持幅ではなく、今回の追加仮定である。
実際の把持成立は、指の閉鎖・接触・滑りを用いる後段の判定が必要となる。
深さはワールド座標の直線距離ではなく、メッシュの材料座標に基づく。

現在の布メッシュは長手間隔12.5mmで、接触マスクは全頂点が帯内の面だけを許可する。
このため深さ30mm点の面は指接触が無効になる。探索自体は30mmまで行い、
それらは `native_contact_face=false` として候補数から除いた。有効面上の位置サンプルは192点である。

傾き0度は布面に沿う接近、負の傾きは接近軸を布の外向き法線と反対側へ傾けたもの。
閉鎖軸は布法線を接近軸に直交する平面へ投影して決める。閉鎖軸と布法線の角度は傾きの絶対値に対応する。

## 判定方法

実際にBakeされた皮膚の1347三角形を用いた。遠方の切断境界だけを閉じ、
交差距離と立体内外の両方を判定した。閉じるための補助面が手に影響しない距離にあることも確認した。
小さな指が足の内部に完全に入っていて表面同士が交差しないケースも除外する。

指の開閉は平行移動なので、各凸部品の始点・終点の凸包が、途中を含む正確な掃引体積になる。
直線接近も同様に、途中の干渉を連続的な体積として検査した。
各位置の代表候補では、接近位置と開口幅の全組み合わせを含む保守的な掃引体積も検査し、
安全が確認できた開口幅区間を0.25mm以下の分解能で出力した。

さらに、皮膚判定を通った全候補を、保存状態の足・下腿凸包で再検査した。
足凸包は `InstallSockFitHull` でforefootのMeshColliderにも使用される形状である。
そのMeshColliderの `convex` は既にfalseだが、入力メッシュ自体が凸包なので、フラグの切り替えでは形は変わらない。
布の接触を解くために足のObiColliderが無効でも、この形状の幾何学的な差は残る。

## 得られた候補と制約

候補は甲側寄りの開口縁付近に集中した。深さ0–10mmが約83%を占める。
実皮膚に対する候補の傾き分布は−60度が9304、−30度が1464、0度が22。
全32姿勢に傾き30度以内の候補はあるが、50mm開いて接近できたものは傾き−60度の候補だった。
浅い角度に限定した場合の最大検査開口幅は5–40mmで、多くの姿勢では10mmだった。
これらはすべて**実皮膚との判定**の結果であり、現在の足凸包で実行可能という意味ではない。

代表例のExcel番号1（pitch50度、roll−30度）では、把持点と実皮膚の距離は約19.82mmだが、
足凸包までは約2.68mmだった。傾き−30度の指は実皮膚から3.25mm以上離れていても、足凸包に交差する。
その姿勢の10→5mm閉鎖と50mm直線接近も、実皮膚には1.66mm以上の余裕がある。

次は、右グリッパーとの剛体接触に使う足の形状を、表示されている実皮膚に合わせることを勧める。
布の安定性を担う既存の足接触処理と分けて検討し、修正後に同じ候補で再検査する。
今回の結果だけから、指定の10mm把持中心を変更する必要があるとは判断しない。

## 出力と再実行

`artifacts/right-grasp-geometry/` に以下を保存した。

- `per-pose-summary.csv`：32姿勢ごとの候補数・開口幅・凸包干渉結果。
- `summary.json`：全体結果と探索条件。
- `gripper-calibration.json`：TCP、関節値、メッシュとURDFのハッシュ。
- `pose-XX/report.json`：その姿勢の全サンプルと全皮膚無干渉候補。
- `pose-XX/candidates.csv`：候補の世界位置、ベース姿勢、URDF関節値、実皮膚の余裕、凸包干渉フラグ。
- `opening-map.png`：実皮膚についての32姿勢の候補分布。
- `foot-proxy-section.png`：代表例の実皮膚・足凸包・指の断面比較。
- `example-candidate.json`：比較図の候補と距離。

```bash
python3 -m pip install -e '.[geometry]'
python3 scripts/search_right_grasp_geometry.py --workers 4
# 皮膚の余裕条件と独立に、元の全グリッドを足凸包でも検査
python3 scripts/check_right_grasp_foot_proxy.py --all-grid --workers 4
# 図を生成する場合はmatplotlibが必要
python3 scripts/report_right_grasp_geometry.py
python3 -m pytest tests/test_grasp_geometry.py tests/test_grasp_feasibility.py -q
```

実行環境はpython-fcl 0.7.0.6、trimesh 4.12.2。幾何関連11テストを通過した。
同じ全探索を2回実行し、各姿勢の候補数・判定数の一致も確認した。

腕のIK、他のロボットリンクとの自己干渉、対象外の布との干渉、接触ロールアウト、把持・保持成功は未検証である。
